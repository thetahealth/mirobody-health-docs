Mirobody Cloud 提供托管的 `/v1` API，用于保存健康数据、标准化读数并基于记录回答问题。你的应用负责收集数据，再将其发送给服务。产品概览与自部署路径见 [Mirobody](/zh)。

## 开始使用

<CardGroup cols={2}>
  <Card title="完成第一次调用" icon="rocket" href="/zh/api-reference/quickstart">

  <Card title="选择 API" icon="signs-post" href="/zh/api-reference/choose-your-api">

## 数据入口 {#data-inputs}

按来源的数据形态选择端点。同一个 Subject 的所有调用应使用相同的 `user` 值。

| 数据 | 端点 | 结果 |
| --- | --- | --- |
| 设备读数及其他结构化记录 | [`POST /v1/data`](/zh/api-reference/data) | 保存的读数，以及规范化后的名称和单位 |
| 报告、照片或表格 | [`POST /v1/files`](/zh/api-reference/files) | 保存的源文件和提取出的读数 |
| 叙事文本或提取结果预览 | [`POST /v1/standardize`](/zh/api-reference/extract) | 同步返回的标准化结果 |
| 主观日记 | [`POST /v1/responses`](/zh/api-reference/responses) 并设置 `store: true` | 保存的对话条目 |

[快速开始](/zh/api-reference/quickstart)提供完整的结构化记录请求。[API 概览](/zh/api-reference/overview)说明认证、Subject、错误和留存。

## 处理阶段

<Steps>
  <Step title="① 收集">
    你的应用获取设备数据、用户上传的报告或手动记录，再通过上表对应的端点提交。
  </Step>
  <Step title="② 转译">
    服务将检查项目名称匹配到 LOINC 编码，并使用 UCUM 解析单位。如何检查结果见[标准化](/zh/api-reference/standardization)。
  </Step>
  <Step title="③ 智能体">
    通过[问答 API](/zh/api-reference/chat)查询已保存的记录，或通过[智能体 API](/zh/api-reference/responses)构建 agent。
  </Step>
</Steps>

## 问答与智能体 API

| 用途 | 端点 | 适用场景 |
| --- | --- | --- |
| 有数据依据的回答 | [`POST /v1/chat/completions`](/zh/api-reference/chat) | 提出一个问题，获得附有健康记录依据的回答 |
| 智能体工作流 | [`POST /v1/responses`](/zh/api-reference/responses) | 使用工具、对话状态与流式输出 |

两者均采用兼容 OpenAI 的请求格式。可运行的 Python 和 Node 示例见 [SDK 示例](/zh/api-reference/sdk-examples)。
