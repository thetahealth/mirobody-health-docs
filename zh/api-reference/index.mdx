**Mirobody Cloud** 是开源 Mirobody 引擎的托管形态。由我们运维存储、模型与密钥，并以兼容 OpenAI 的 `/v1` 接口对外提供，因此现有的 OpenAI SDK 只需改一个 base URL 和一个密钥即可接入。结构化读数的标准化与你自己运行的引擎完全一致。Mirobody 是什么、Cloud 与自部署如何比较，见[概览](/zh)；在自己的基础设施上运行，请看[开源部署](/zh/self-host)标签页。

最快跑通一次调用的路径是[快速开始](/zh/api-reference/quickstart)：创建密钥、写入两条样例读数、提一个问题。

## Cloud 上的三个步骤

引擎只做三件事：**① 收集 → ② 转译 → ③ 智能体**。Cloud 就是同样这三件，只是运维那一半由我们承担。有一处差别需要说明：在 Cloud 上，**收集发生在你那一侧。** 数据由你获取（设备 OAuth、App 内采集、用户上传一份报告），交给我们；我们负责托管、标准化，并把它交给 AI 回答。

<Steps>
  <Step title="① 收集：按数据形态选对入口">
    结构化读数走 [`POST /v1/data`](/zh/api-reference/data)。化验 PDF、照片与表格走 [`POST /v1/files`](/zh/api-reference/files)，它保存原件、抽取文本，并把其中的读数标准化。[`POST /v1/standardize`](/zh/api-reference/extract) 同步执行同一套标准化，用于 dry-run 预览，或处理叙事文本。
  </Step>
  <Step title="② 转译：每条结构化读数自动完成">
    名称确定性解析到 **LOINC**（不让 LLM 猜码），值归一到 **UCUM** 单位，编码只匹配、不臆造。`"血糖(空腹)"`、`"FBG"`、`"Glucose, fasting"` 归成一条序列。见[标准化](/zh/api-reference/standardization)。
  </Step>
  <Step title="③ 智能体：让 AI 在其上工作">
    向 [Answers API](/zh/api-reference/chat) 要一条有依据、带证据的回答，或在 [Agent API](/zh/api-reference/responses) 上构建完整 agent：你自己的工具、存储的对话，openai-agents SDK 开箱即用。回答是标准化数据最直接的用法，而同一批记录也让你可以发掘洞察、生成报告或发出预警。
  </Step>
</Steps>


## 两个 API 接口，一套引擎

<CardGroup cols={2}>
  <Card title="Agent API（推荐）" icon="robot" href="/zh/api-reference/responses">
    `POST /v1/responses`（兼容 OpenAI Responses）。你的 function 工具、`previous_response_id` / `session_id` 状态、`response.*` 流式。openai-agents SDK 只需改 base URL。
  </Card>
  <Card title="Answers API" icon="comment-dots" href="/zh/api-reference/chat">
    `POST /v1/chat/completions`。封闭、有据可循的 completion：一个问题、一条有证据的回答。任何 OpenAI SDK 直接替换，也非常适合[作为你自己 agent 里的一个工具](/zh/api-reference/use-as-a-tool)。
  </Card>
</CardGroup>

## 四种数据形态与对应端点

这就是控制台**数据**页提供的同样三种来源，再加上日记这一种。

| 来源 | 端点 |
| --- | --- |
| **文件 / 照片** —— 化验单、体检 PDF、手机照片 | [`POST /v1/files`](/zh/api-reference/files) |
| **结构化记录** —— 首要是设备与可穿戴数据，另有手动记录 | [`POST /v1/data`](/zh/api-reference/data) |
| **叙事文本** —— 含读数的笔记或报告 | [`POST /v1/standardize`](/zh/api-reference/extract) |
| 纯主观的日记 | [`POST /v1/responses`](/zh/api-reference/responses) 带 `store: true` |

哪种情况用哪个端点、以及可运行的示例，见[快速开始](/zh/api-reference/quickstart)。

## 为什么选 Mirobody

- **有依据，而非听着合理**：回答可附 `health_records`、`citations` 与服务端采集证据时使用的工具步骤。
- **结构化数据标准化**：通过 `/v1/data` 写入或由 `/v1/standardize` 存储的记录都会经过 LOINC + UCUM 编码；你的分析与 agent 读取同一份序列。
- **双重 OpenAI 兼容**：Chat Completions *与* Responses 两个协议；现有 SDK 与 agent 框架直接可用。
- **天生多租户**：一个 key，每个终端用户一个隔离 Subject；按 Subject 的[被遗忘权删除](/zh/api-reference/overview#端点一览)。
- **内核开放**：Cloud 运行的就是同一个[开源引擎](/zh/self-host)，而且是按同样这三个步骤组织的。自己托管时，① 收集也由引擎完成：设备 provider 按计划拉取，术语层在你自己的进程里离线运行。见[快速开始](/zh/quickstart#a--the-library)中作为库使用的方式。
