Mirobody 分三步：**① 收集 → ② 转译 → ③ 提问。** 第一次运行只需要 `curl` 和两条**样例**读数。准备好 Cloud 的 `mb_live_*` 密钥，预留约 10 分钟。示例数据保留一小时；真实数据请按自己的留存策略设置。

<Note>
请在**将要调用的同一区域**创建密钥：[中国区控制台](https://platform.mirobody.cn/)或[全球区控制台](https://platform.mirobody.ai/)。登录后打开 **API Keys** 创建密钥，出现时立即复制（只显示**一次**）。在终端设置对应的 API 地址和密钥。下面默认中国区；如果账户在全球区，改用注释中的全球区地址：

```bash
export MIROBODY_API_BASE="https://api.mirobody.cn/v1"  # 中国区
# export MIROBODY_API_BASE="https://api.mirobody.ai/v1" # 全球区：改用这一行
export MIROBODY_API_KEY="mb_live_..."
```
</Note>

<Steps>
  <Step title="① 收集：写入两条样例读数">
    <IngestMentalModel />

    用 [`POST /v1/data`](/zh/api-reference/data) 写入结构化读数，`retention` **必填**。下面每一步都使用相同的 `user`，保证操作的是同一个 Subject。

    ```bash
    curl "$MIROBODY_API_BASE/data" \
      -H "Authorization: Bearer $MIROBODY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
            "user": "docs-demo",
            "retention": "1h",
            "records": [
              {"indicator": "fasting_glucose", "value": 97, "unit": "mg/dL", "time": "2026-06-16T07:30:00Z"},
              {"indicator": "FBG",             "value": 92, "unit": "mg/dL", "time": "2026-06-17T07:25:00Z"}
            ]
          }'

    ```

    预期 JSON 响应包含 `"status": "ok"`、`"ingested": 2` 和 `"subject": "docs-demo"`；`standardized` 表示成功匹配 LOINC 编码的条数。重复执行会增加记录：[写入不具备幂等性](/zh/api-reference/data#写入记录)。

    `user` 是[租户隔离键](/zh/api-reference/overview#多租户user-字段)。在应用中为每位终端用户传入各自稳定、不同的 id。
  </Step>

  <Step title="② 转译：数据带着编码返回">
    注意上面的两种写法：`fasting_glucose` 和 `FBG`。把数据读回来，两行都带有**同一个 LOINC 编码**、规范名称和 UCUM 解析后的值：

    ```bash
    curl "$MIROBODY_API_BASE/data?user=docs-demo&limit=10" \
      -H "Authorization: Bearer $MIROBODY_API_KEY"
    ```

    ```json
    {
      "object": "list",
      "data": [
        {
          "indicator": "FBG",
          "value": "92",
          "parsed_value": "92",
          "parsed_unit": "mg/dL",
          "loinc_code": "1558-6",
          "canonical_name": "Fasting glucose [Mass/volume] in Serum or Plasma",
          "time": "2026-06-17T07:25:00+00",
          "source": "api",
          "comment": ""
        },
        {
          "indicator": "fasting_glucose",
          "value": "97",
          "parsed_value": "97",
          "parsed_unit": "mg/dL",
          "loinc_code": "1558-6",
          "canonical_name": "Fasting glucose [Mass/volume] in Serum or Plasma",
          "time": "2026-06-16T07:30:00+00",
          "source": "api",
          "comment": ""
        }
      ],
      "has_more": false,
      "subject": "docs-demo"
    }
    ```

    对一个新 Subject，响应应包含两种名称，它们的 `loinc_code` 相同；ID 等其他字段可能变化。`value` 是字符串形式的原始数值，解析后的单位另列。这就是[标准化管线](/zh/api-reference/standardization)：确定性的名称→LOINC（不让 LLM 猜码）+ UCUM，作用于每次结构化记录写入。
  </Step>

  <Step title="③ 提问：得到有依据的回答">
    用**相同的** `user` 调用[问答 API](/zh/api-reference/chat)。它可以查询刚写入的两条数据，包括名称为 `FBG` 的那条：

    ```bash
    curl "$MIROBODY_API_BASE/chat/completions" \
      -H "Authorization: Bearer $MIROBODY_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
            "model": "mirobody-flash",
            "user": "docs-demo",
            "messages": [{"role": "user", "content": "What fasting glucose readings did I add?"}]
          }'
    ```

    回答在 `choices[0].message.content` 中。`health_records` 和 `message.tool_steps` 能帮助你查看用到了哪些记录和服务端工具；具体内容每次可能不同。如果需要自己的工具或对话状态，请继续阅读[智能体 API](/zh/api-reference/responses) 和 [SDK 示例](/zh/api-reference/sdk-examples)。使用 agent SDK 时也要传入同一个 Subject，否则会读取账户默认 Subject。
  </Step>
</Steps>

## 调用失败时

遇到 `401`，先确认密钥与 `MIROBODY_API_BASE` **属于同一区域**，再检查 Bearer 请求头；遇到 `400`，根据[错误参考](/zh/api-reference/overview#错误格式)中的 `error.code` 和 `error.param` 定位字段；遇到 `429`，阅读[限流与配额](/zh/api-reference/rate-limits)，区分速率限制与配额耗尽。

## 其他数据来源

化验报告可通过[文件接口](/zh/api-reference/files)上传 PDF、照片或表格。想同步预览提取出的读数，可用 [`POST /v1/standardize`](/zh/api-reference/extract) 提交文件或已上传的 `file_key`。批量写入设备读数见[结构化记录](/zh/api-reference/data)。这些路径都遵守相同的 `user` 隔离规则。

## 控制台演练场

控制台演练场采用相同流程：**① 采集数据 → ② 自动标准化 → ③ agent 或问答**。无需写代码即可上传文件、查看抽取文本或标准化记录，并试用两个 API。请打开**与你账户同一区域**的控制台，用量统计在其侧栏。
