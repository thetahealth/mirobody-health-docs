配置由一组 YAML 文件加上环境变量组成。随仓库提供的文件已经是可用于本地运行的默认值：部署时把各项密钥写进 `.env`，在那里或在首次设置页上选择模型，再在一个覆盖文件里修改少数需要改的设置即可。

## 配置文件

| 文件 | 内容 | 是否修改 |
| --- | --- | --- |
| `config.yaml` | 服务端、数据库、登录、扩展目录 | 不修改：在覆盖文件中覆盖它的值 |
| `config.llm.yaml` | 模型表（`MODELS`）、每个用途使用哪个条目，以及首次设置页为本地运行提供的选项（`LOCAL_SETUP`） | 需要新增模型时 |
| `config.devices.yaml` | Garmin、Oura、Whoop 的凭据；Google 与 Apple 登录 | 需要启用某个 provider 时 |
| `config.{ENV}.yaml` | `config.yaml` 的覆盖文件，可选：在 `.env` 的 `MIROBODY_CONFIG_FILE` 中指定一份；`./deploy.sh` 只会沿用旧版本已经生成的覆盖文件 | 修改 |
| `.env` | `ENV`、自动生成的各项密钥与设置令牌、模型 API 密钥或本地模型服务的地址，以及运行模型的 Compose profile | 修改 |

后加载的来源优先：环境变量，其次是覆盖文件，再次是 `config.devices.yaml` 与 `config.llm.yaml`，最后是 `config.yaml`。**字典不会跨文件合并**：覆盖文件里设置的键会替换整个值，所以在覆盖文件里设置 `EMAIL_PREDEFINE_CODES` 会替换掉演示账号，而不是在其后追加。

`ENV` 只决定加载哪个覆盖文件，并标记日志行，本身不带任何行为。生产模式由下文的 `PRODUCTION` 开关声明，而不是由环境名决定。

覆盖文件中，名称含有 `_KEY`、`_PASSWORD`、`_PASS`、`_PWD`、`_SECRET`、`_SK` 或 `_TOKEN` 的值，会用 `.env` 里的 `CONFIG_ENCRYPTION_KEY` 加密保存。

## 模型 {#the-model-key}

每个用途都由一个模型厂商密钥**或者**本地模型驱动。首次设置页（尚未设置模型时 `./deploy.sh` 会打印它的链接；之后在**设置 › 模型**中）把两种选择之一加密保存到数据库，无需重启即可生效，并且从不覆盖 `.env` 中已设置的值。保存需要 `.env` 中的 `SETUP_TOKEN`；一旦设置过模型，还需要已登录的会话。

### 模型厂商密钥

把下列任意一个写进 `compose.yaml` 旁边的 `.env`，然后使其生效：

<Fact k="llmKeys" code sep="、" />

```bash
docker compose up -d
```

`docker compose restart` 不会重新读取 `.env`，`up -d` 才会。`./deploy.sh` 会把其环境中给出的密钥写进 `.env`（`OPENROUTER_API_KEY=sk-or-... ./deploy.sh`），所以首次运行不需要第二步。

每个密钥为三个用途各选一个模型：对话（模型选择器）、视觉（化验单照片与扫描页）、文本（指标抽取、文件标题、摘要与日志句子）。<OssLink path="config.llm.yaml" /> 开头的表格列出了每个密钥选中的模型，以及各密钥的申请地址。模型名可以自己改：首次设置页在密钥旁显示它，在 `.env` 中则由每个条目以 `model_env` 命名的变量（例如 `OPENROUTER_CHAT_MODEL`）替换；厂商模型会先用一次真实请求验证再保存。

### 本地模型 {#local-models}

没有密钥时，`config.llm.yaml` 的 `local`、`local-utils` 与 `local-ocr` 条目从你机器上一个 OpenAI 兼容的服务为所有用途提供模型。Mirobody 自带预设的运行时是 [llama.cpp](/zh/local-models) 的 `llama-server`：首次设置页会找到这个服务，列出它提供的模型，并加载你选的规模。同样的选择写在 `.env` 中是：

```bash
LOCAL_BASE_URL=http://host.docker.internal:8080/v1        # 应用在 Docker 里，llama-server 在宿主机上
LOCAL_OCR_BASE_URL=http://host.docker.internal:8080/v1    # 用 Compose profile 时两者都写 http://llama:8080/v1
LOCAL_MODEL=minicpm5-2b                                   # 回答问题的模型：minicpm5-2b（小，默认）或 qwen3.8-27b（大）
LOCAL_OCR_MODEL=glm-ocr                                   # 读文档的模型
COMPOSE_PROFILES=local-cpu                                # 在 CPU 上把 llama.cpp 跟栈一起运行；NVIDIA 显卡用 `local`
```

`UTILS_OCR_MODEL` 是第四个用途：一个文档 OCR 模型，先于其他模型读取化验单照片与扫描页，其中的表格按表头规则读取、不经模型。随仓库提供的值是 `local-ocr` 条目。`.env` 中的 `HF_ENDPOINT` 可把一次性的模型下载指向 Hugging Face 镜像。

`.env` 中的厂商密钥优先于本地条目，只要密钥还在，首次设置页就会拒绝**100% 在本机运行**。要在保留密钥的同时使用本地模型：

```bash
DEFAULT_MODEL=local
UTILS_VISION_MODEL=local-utils
UTILS_TEXT_MODEL=local-utils
```

### doctor 报告

`mirobody doctor` 打印找到的密钥与本地模型服务、每个用途选中的条目，并对没有可用模型的用途给出修复方法。`--probe` 向每个用途发送一次真实请求（一次工具调用、一个按 schema 约束的回答、一张图片、OCR 的两遍识别），并检查本地服务运行的确实是条目中指定的模型；在厂商那里要花几个 token，在本地模型上要花几分钟。

```bash
docker compose exec mirobody mirobody doctor           # Docker 栈
docker compose exec mirobody mirobody doctor --probe   # 每个用途一次真实请求
mirobody doctor                                        # 源码检出或 pip 安装
```

服务端与 worker 启动时也会在日志中输出同样的报告。

### 更换模型

- **让某个用途改用另一条配置。** `UTILS_VISION_MODEL`、`UTILS_TEXT_MODEL` 和 `UTILS_OCR_MODEL` 可以取一个条目名、一组条目名（取第一个有密钥或有服务的）、`provider/model` 字符串，或一条内联配置。同名环境变量优先于文件，例如 `UTILS_VISION_MODEL=qwen-utils`。
- **修改对话的默认模型。** `DEFAULT_MODEL` 指定一个 `MODELS` 条目；不设置时，默认取第一个有密钥或有服务的条目。
- **让某个密钥经由另一个网关。** 在 `.env` 中设置 `<PREFIX>_BASE_URL`（`PREFIX` 是密钥名去掉 `_API_KEY`），读取该密钥的所有条目都会改用另一个兼容 OpenAI 的端点，例如 `OPENROUTER_BASE_URL`。Anthropic 自己的 SDK 也读取 `ANTHROPIC_BASE_URL`，如果机器上已经为其他工具设置了它，Mirobody 也会随之改道；`mirobody doctor` 会打印每个用途实际解析到的端点。
- **接入其他厂商。** 在 `config.llm.yaml` 的 `MODELS` 中新增一条，写明 `llm_type: openai`、`base_url`、`model`，并把 `api_key` 设为保存密钥的 `.env` 变量的*名称*。用于视觉的条目必须声明 `supports_image: true`。请直接加在 `config.llm.yaml` 中：覆盖文件里的 `MODELS` 会替换整张表。

## 部署设置

| 键 | 默认值 | 何时修改 |
| --- | --- | --- |
| `PRODUCTION` | `false` | 部署面向你以外的人。此时只要还有预置登录码或任何 `REPLACE_THIS_VALUE_IN_PRODUCTION` 占位值，服务端就拒绝启动，并且不会写入演示数据。 |
| `SEED_DEMO_DATA` | `true` | 部署将保存真实数据。在首次启动前于 `.env` 中设为 `false`，两个演示账号都不会创建。 |
| `EMAIL_PREDEFINE_CODES` | 两个演示账号 | 面向网络部署前一律修改：删除它，改用真实登录。 |
| `BOOTSTRAP_SCHEMA` | `true` | 你自行管理数据库 schema。为 `true` 时，每次启动都会重放 schema 文件。 |
| `MCP_PUBLIC_URL` | 未设置 | 部署有公网 HTTPS 地址时，见[在服务器上部署](/zh/deployment/production#public-url-and-https)。 |
| `MCP_URL_TTL_DAYS` | <Fact k="mcpUrlTtlDays" /> | 需要缩短或延长个人 MCP URL 的有效期（天）。 |
| `DEFAULT_TIMEZONE` | `America/Los_Angeles` | 用户主要在其他时区。取 IANA 时区名；用户自己的设置优先。 |
| `HTTP_HEADERS` | 未设置 | 其他源上的浏览器客户端需要 CORS 头。 |
| `REQUEST_RATE_LIMITER` | 按路径的限额 | 需要调整登录与对话的限流（每分钟请求数）。 |
| `ENABLE_INDICATOR_EXTRACTION` | `1` | 上传的文件只保存、不抽取读数时设为 `0`。 |

决定 agent 行为的键见[内置 Agent](/zh/tools/agents#configuration)。

## 密钥

| 密钥 | 位置 | 由谁设置 |
| --- | --- | --- |
| `PG_PASSWORD`、`PG_ENCRYPTION_KEY`、`CONFIG_ENCRYPTION_KEY`、`LOG_ENCRYPTION_KEY`、`JWT_KEY` | `.env` | `./deploy.sh`，首次运行时用 `openssl rand -hex 32` 生成 |
| `SETUP_TOKEN` | `.env` | `./deploy.sh`。首次设置页改变健康数据的去向之前必须出示它；一旦设置过模型，还需要已登录的会话，带令牌的链接也不再打印。 |
| `DATABASE_DECRYPTION_KEY` | `config.devices.yaml`，或在 `.env` 中覆盖 | 你自己。随仓库提供的是 `REPLACE_THIS_VALUE_IN_PRODUCTION` 占位值；环境变量的优先级高于任何配置文件。 |

`PG_ENCRYPTION_KEY` 与 `CONFIG_ENCRYPTION_KEY` 是两个不同的值：前者加密存储的内容，例如对话消息与上传的文件。`DATABASE_DECRYPTION_KEY`（十六进制）加密各 provider 保存的设备凭据。不要在不同环境之间复制这些密钥。自行生成这些密钥并迁移到另一台主机的方法，见[在服务器上部署](/zh/deployment/production#secrets)。

## 扩展目录

引擎启动时扫描三组目录。新增一个目录即可扩展引擎，无需修改代码包。

| 键 | 默认值 | 内容 |
| --- | --- | --- |
| `MCP_TOOL_DIRS` | `mirobody/agent/tools` | 工具模块，见[添加工具](/zh/tools/adding-tools) |
| `AGENT_DIRS` | `mirobody/agent` | agent 类，见[内置 Agent](/zh/tools/agents#replacing-the-agent) |
| `PROVIDER_DIRS` | `mirobody/collect/providers` | 设备 provider，见[编写 Provider](/zh/development/provider-integration) |

在覆盖文件中设置其中任何一项都会替换整个列表，所以请把默认条目和你自己的目录一起写上。已安装的包也可以通过 `mirobody.tools`、`mirobody.agents` 与 `mirobody.providers` 入口点扩展这三项。

所有配置键的完整说明见 <OssLink path="mirobody/utils/config/README.md" />。
