Docker 会启动 Web 应用、Postgres 数据库、后台 worker 和演示数据。准备好 Docker 与 Compose 即可，无需另装 Python、Node.js 或显卡；Windows 用户请在 WSL 2 终端操作。项目采用 Apache 2.0 许可，源码见 [GitHub](https://github.com/thetahealth/mirobody)。

## 启动与试用 {#first-local-result}

<Steps>
  <Step title="启动服务">
    ```bash
    git clone --depth 1 https://github.com/thetahealth/mirobody.git && cd mirobody
    ./deploy.sh
    ```

    脚本会调用 OpenSSL 生成密钥并写入 `.env`，下载应用镜像，启动演示环境，最后输出设置页链接。
  </Step>
  <Step title="选择模型">
    打开终端中显示的链接，填写模型 API 密钥：OpenRouter、OpenAI、Gemini、Anthropic、DeepSeek、DashScope，或任何 OpenAI 兼容网关。密钥通过实际请求验证后才会加密保存；之后可在**设置 › 模型**中修改，无需重启。若要让所有模型都在本机运行，见[模型的运行位置](#models)。
  </Step>
  <Step title="登录并提问">
    打开 <Fact k="url" code />，在「邮箱验证码」标签用 `you@mirobody.ai` 和验证码 `111111` 登录。问「我的胆固醇有什么变化？」：回答会画出趋势，并标出每个数字来自哪份文件。然后在**数据**页上传 `demo/upload/` 中的一份文件，或切换到 `mom@mirobody.ai` 共享给你的档案。
  </Step>
</Steps>

[完整演示](/zh/walkthrough)用同一份记录走完五个场景。保存真实记录前，请在**首次启动前**按照[在服务器上部署](/zh/deployment/production)完成设置；运行过演示环境后，请按[已有演示环境路径](/zh/deployment/production#after-a-local-demo)使用全新的数据卷。

<AccordionGroup>
  <Accordion title="检查服务状态">
    在引擎仓库目录执行：

    ```bash
    docker compose ps
    curl -fsS http://localhost:18060/api/health
    docker compose exec mirobody mirobody doctor
    ```

    `mirobody` 服务应为 `healthy`，健康检查返回 `version` 和 `agent`。`mirobody doctor` 列出每个模型用途选中的条目；加上 `--probe` 会向每个用途发送一次真实请求。之后才在 `.env` 中添加 Key 时，请运行 `docker compose up -d`；`docker compose restart` 不会重新读取 `.env`。常见故障见[故障排查](/zh/troubleshooting)。
  </Accordion>
  <Accordion title="这台机器没有 Git">
    也可以直接下载并解压源码：

    ```bash
    curl -L https://github.com/thetahealth/mirobody/archive/refs/heads/main.tar.gz | tar xz && cd mirobody-main
    ```
  </Accordion>
</AccordionGroup>

## 模型的运行位置 {#models}

| | 使用模型 Key | 100% 在本机运行 |
| --- | --- | --- |
| 由谁运行模型 | 你填写 Key 的那家服务商 | [llama.cpp](/zh/local-models) 的 `llama-server`，与服务一起运行或运行在宿主机上 |
| 你需要 | Docker 和一个 Key | Docker；默认规模需要 16 GB 内存，其中至少 8 GB 分配给 Docker |
| 速度 | 取决于所选模型和服务 | 建议使用 GPU；只用 CPU 时，一次回答可能需要几分钟 |

若要让模型在 Docker 中随服务一起运行，用 Compose profile 启动，代替单独的 `./deploy.sh`：

```bash
COMPOSE_PROFILES=local-cpu ./deploy.sh     # 任何电脑，不需要显卡
COMPOSE_PROFILES=local ./deploy.sh         # NVIDIA 显卡
```

这两种启动方式会自动配置模型连接，首次提问前需要等待模型下载。在 Mac 上，请在宿主机运行 `llama-server`，以便使用 GPU。各平台的安装步骤见[本地运行](/zh/local-models)，不同方案的适用场景见[选择模型](/zh/model-choice)。`.env` 中的云端 API 密钥优先；如需明确使用本地模型，请按[配置说明](/zh/configuration#local-models)设置。

## 离开这台机器的数据 {#what-leaves-the-machine}

健康记录保存在你自己的 Postgres 数据库中，Mirobody 不上报使用统计。是否向外部服务发送数据，取决于你启用的功能：

| | 使用模型 Key | 100% 在本机运行 |
| --- | --- | --- |
| 你的文档和提问 | 发给该服务商，受其条款约束；按表头在本机读出的表格行除外 | 留在本机 |
| 名称到编码、单位到 UCUM（② 转译） | 在本机，查包内词表，不联网 | 同左 |
| 模型权重 | 无 | 从 Hugging Face 下载一次；`.env` 中的 `HF_ENDPOINT` 可指定镜像 |
| 设备厂商（Garmin、Oura、Whoop） | 只在你连接之后：它的令牌和你自己的数据 | 同左 |
| 容器镜像 | 从 Docker Hub 拉取，无法访问时使用镜像站（`.env` 中写 `DOCKER_MIRROR=` 可关闭） | 同左，另加 llama.cpp 的镜像 |
| 登录邮件 | 仅在配置 `EMAIL_SMTP_HOST` 之后：邮箱地址和验证码，发往你自己的邮件服务器 | 同左 |

落盘加密覆盖聊天、上传的文件、用药文字和个人资料，尚未覆盖读数和基因型。应用只在 `127.0.0.1` 上监听；接入你无法控制的网络之前，请先阅读 <OssLink path="SECURITY.md" />，其中列出了服务端会访问的所有地址。

## 导出与备份 {#export-and-backup}

读数可导出为 CSV 或 JSON，可见记录以 NDJSON 流式导出，基因型可导出为 VCF 或 FHIR；`shell/backup.sh` 生成数据库和上传文件的完整副本。接口与限制见[导出数据](/zh/deployment/export)。

## 参与贡献 {#contributing}

最有价值的贡献，是找出解析器答错的术语。运行 `mirobody resolve "<术语>"`；结果错误或为空时，请[提交 issue](https://github.com/thetahealth/mirobody/issues)，或在 <OssLink path="mirobody/res/loinc/resolver_overrides.tsv" /> 中加一行，并在 <OssLink path="mirobody/tests/test_engine_coverage.py" /> 中加一个用例。完整流程见 <OssLink path="CONTRIBUTING.md" />；安全问题请按 <OssLink path="SECURITY.md" /> 的说明通过私有通道报告。
