凡是能运行 Python <Fact k="python" /> 或 Docker 的地方都能运行 Mirobody：笔记本、本地服务器或云主机。引擎以 Apache 2.0 许可开源，仓库是 [thetahealth/mirobody](https://github.com/thetahealth/mirobody)。它保存的记录留在你自己运维的 Postgres 里；使用本地模型时，你的每个提问和每份文档也都留在这台机器上。Mirobody 是什么，以及自部署与 Mirobody Cloud 的区别，见[概览](/zh)。

## 运行方式

按你的目的选一行即可，三者是互相替代的选择，不是先后步骤。

| 你想要 | 方式 | 需要 | 模型 |
| --- | --- | --- | --- |
| 在自己的代码里解析指标名称与单位 | [作为库使用](/zh/quickstart#a--the-library) | Python <Fact k="python" /> | 不需要：词表随包发布 |
| 运行完整产品，并带有演示数据 | [Docker 栈](/zh/quickstart#b--the-stack) | 带 Compose 的 Docker；Git 可选，源码压缩包就是同一份检出 | 一个模型厂商密钥，**或者**[让所有模型都在本机运行](/zh/local-models) |
| 修改代码并查看效果 | [源码检出](/zh/quickstart#c--a-checkout) | Python 与带 pgvector 的 Postgres | 一个模型厂商密钥，或一个本地模型服务 |

Docker 栈由三个容器组成：带 pgvector 的 Postgres、服务端与后台 worker；用 Compose profile 运行本地模型时，还有一个 `llama` 服务跟在旁边。自带的 Web 客户端运行在 <Fact k="url" code />。

## 模型的运行位置 {#models}

读报告、回答问题、写摘要，模型在你指定的地方运行。首次设置页只问一次；之后在**设置 › 模型**中修改，无需重启。

| | 模型在哪里运行 | 你需要 | 什么会离开这台机器 |
| --- | --- | --- | --- |
| **模型厂商密钥** | 在你粘贴密钥的那家厂商：OpenRouter、OpenAI、Gemini、Anthropic、DeepSeek、DashScope，或任何 OpenAI 兼容网关 | Docker 和一个密钥 | 你的提问、agent 读到的数据行，以及文档的页面图像和文字，都会发给那家厂商，受其条款约束；按表头规则读出的表格行留在本机 |
| **100% 在本机运行** | 跟栈一起运行的 [llama.cpp](/zh/local-models)（`llama-server`），Mirobody 自带预设的本地模型运行时：GLM-OCR 读文档，另一个回答问题的模型由你选规模 | Docker，加上所选规模需要的内存与磁盘；[本地运行](/zh/local-models#choose-a-size)列出每种规模下载多少、需要什么 | 与你有关的任何数据都不会离开；模型权重从 Hugging Face 下载一次 |
| **只用库** | 不需要模型：`pip install mirobody` 把名称解析到 LOINC、单位换算到 UCUM | Python <Fact k="python" /> | 什么都不会离开：词表随包发布 |

首次设置页提供两档规模：小（默认，任何 16 GB 内存的电脑都能运行）和大，两者只有回答问题的模型不同。每种规模都用同一个 GLM-OCR 模型读文档，表格按表头规则读取、不经模型，所以化验单的读数结果一样；不同的是回答得多好、多快，以及聊天里的照片是被模型看到，还是只读出其中的文字。`.env` 中的厂商密钥优先于本地模型，[配置](/zh/configuration#local-models)里有反过来的三个变量。[选择模型](/zh/model-choice)在同一评测上比较这两档规模与五个云端模型，并说明每种方式把什么发到哪里。

## 第一次在本地运行 {#first-local-result}

安装 Docker Compose 后，启动本地演示环境，选择模型的运行位置，再检查预置读数。查看样例读数既不需要密钥也不需要模型；读文档和提问二者取其一。

<Steps>
  <Step title="启动演示环境">
    检出引擎并启动服务。脚本把各项密钥写进 `.env`，拉取应用镜像，创建演示账号和样例读数，最后打印访问地址；尚未设置模型时，打印的是首次设置页的链接。

    ```bash
    git clone --depth 1 https://github.com/thetahealth/mirobody.git && cd mirobody
    ./deploy.sh
    ```
  </Step>
  <Step title="选择模型的运行位置">
    打开打印出的链接。粘贴一个模型厂商密钥（要先用一次真实请求验证通过才会保存），或者选择**100% 在本机运行**：页面在这台电脑上寻找 `llama-server`，列出它提供的模型，并加载你选的规模。各平台的启动命令见[本地运行](/zh/local-models)。选择加密存储，无需重启即可生效。手上已有密钥时，`OPENROUTER_API_KEY=sk-or-... ./deploy.sh` 会跳过这一页。
  </Step>
  <Step title="检查服务状态">
    在引擎仓库目录执行：

    ```bash
    docker compose ps
    curl -fsS http://localhost:18060/api/health
    docker compose exec mirobody mirobody doctor
    ```

    `mirobody` 服务应为 `healthy`，健康检查会返回 `version` 和 `agent`。最后一条命令在**容器内**说明每个模型用途选中了哪个条目；`mirobody doctor --probe` 会向每个用途发送一次真实请求。之后才在 `.env` 中添加密钥时，请运行 `docker compose up -d`；`docker compose restart` 不会重新读取 `.env`。
  </Step>
  <Step title="查看样例读数">
    打开 <Fact k="url" code />，在「邮箱验证码」页签用 `you@mirobody.ai` 和验证码 `111111` 登录，再打开 **Data**。页面应显示预置读数。[快速开始](/zh/quickstart#b--the-stack)也介绍了演示上传文件和其他运行方式。
  </Step>
</Steps>

保存真实记录前，请在**首次启动前**按照[在服务器上部署](/zh/deployment/production)设置。已经运行过演示环境时，请按[已有演示环境路径](/zh/deployment/production#after-a-local-demo)使用全新数据卷。

## 离开这台机器的数据 {#what-leaves-the-machine}

你的记录保存在你自己的 Postgres 里、运行在你自己的容器中，这里没有任何使用情况上报。什么会离开，取决于由谁来读它：

| | 使用模型厂商密钥 | 100% 在本机运行 |
| --- | --- | --- |
| 你的文档与提问 | 发给那家厂商，受其条款约束；按表头规则读出的表格行除外 | 留在本机 |
| 名称到编码、单位到 UCUM（② 转译） | 在本机完成，来自包内的词表，不联网 | 相同 |
| 模型权重 | 无 | 从 Hugging Face 下载一次；`.env` 中的 `HF_ENDPOINT` 可指定镜像 |
| 设备厂商（Garmin、Oura、Whoop） | 只在你绑定之后：它的令牌和你自己的数据 | 相同 |
| 容器镜像 | 由 `./deploy.sh` 从 Docker Hub 拉取，Docker Hub 无响应时改用镜像源（`.env` 中 `DOCKER_MIRROR=` 可关闭镜像源） | 相同；用 Compose profile 运行模型时，再加上 llama.cpp 的镜像 |
| 登录邮件 | 仅在配置了 `EMAIL_SMTP_HOST` 之后：邮箱地址和验证码，发给你自己的邮件服务器 | 相同 |

静态加密覆盖对话、上传的文件、用药文本和你的档案，读数与基因型暂未覆盖。在它接触你不能控制的网络之前，请先阅读 <OssLink path="SECURITY.md" />，其中列出了服务端可能调用的每一个地址。

## 导出与备份 {#export-and-backup}

记录是你的，可以随时带走。读数可导出为 CSV 或 JSON；可见记录可整体以 NDJSON 流式导出，末尾的 footer 会说明是否完整；基因型可导出为 VCF 或 FHIR；`shell/backup.sh` 生成唯一的完整副本：数据库与上传的文件，按文档中的步骤即可恢复。各接口及其限制见[导出数据](/zh/deployment/export)。

## 部署对外提供的入口

| 入口 | 地址 | 使用者 |
| --- | --- | --- |
| Web 客户端 | `/` | 终端用户：在 `/data` 管理文档与读数，在 `/ask` 向 agent 提问，以及关爱圈共享 |
| HTTP API | `/api/*` | 你自己的应用；从[本地 HTTP API 指南](/zh/http-api)开始 |
| MCP 端点 | `/mcp` | Claude Code、Codex、Cursor、Gemini CLI、经 `mcp-remote` 的 Claude Desktop，或你自己的 agent 循环，见 [MCP 接入](/zh/tools/mcp-integration) |

自部署的引擎不提供 Cloud 的 `/v1` 接口。那一套接口在云端标签页中说明，上表列出的是引擎自身的路由。

## 参与贡献 {#contributing}

最有价值的贡献是修正解析器解析错的术语。运行 `mirobody resolve "<术语>"`，如果结果错误或为空，可以提交 issue，或者在 <OssLink path="mirobody/res/loinc/resolver_overrides.tsv" /> 中加一行，并在 <OssLink path="mirobody/tests/test_engine_coverage.py" /> 中加一个用例。覆盖率得分就是评审标准。

开发环境安装测试依赖后，运行测试套件与导入约束检查：

```bash
pip install -e '.[test]' && pytest -q && lint-imports
```

完整的贡献流程见 <OssLink path="CONTRIBUTING.md" />，测试的组织方式见 <OssLink path="docs/testing.md" />。

`benchmarks/` 目录下的两个公开基准可以在克隆下来的仓库里直接运行，不需要任何私有数据：`python -m unittest benchmarks.health_records.test_cases`（13 条合成读数与 26 句主诉短语，覆盖五种语言，核对各自的 LOINC/UCUM 与 ICPC-3 结果）以及 `python -m unittest discover -s benchmarks/genomics -p 'test_*.py'`（13 个公开的 1000 Genomes 位点调用，覆盖十种文件形态）。参见 <OssLink path="benchmarks/health_records/README.md" /> 与 <OssLink path="benchmarks/genomics/README.md" />。
