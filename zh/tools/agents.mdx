在 Web 客户端的 `/ask` 页面或对话 API 中，内置 agent 会根据当前选中用户的健康记录回答问题。如果你使用 Claude Code、Codex、Cursor 等外部 agent，可以通过 [MCP](/zh/tools/mcp-integration)接入。

## 可用能力

| 需求 | 使用方式 |
| --- | --- |
| 比较健康数据 | 查询指标、用药和基因数据，详见[健康数据工具](/zh/tools/overview)。 |
| 查阅原始资料 | 搜索和阅读该用户上传的文件及文档库。 |
| 计算与分析 | 通过 `python_exec` 在本地容器中计算查询返回的原始数据，配置方法见[本地 Python 分析](/zh/tools/python-analysis)。 |
| 查找医学资料 | 检索本地医学资料库；启用联网检索后，还可查询 PubMed 和 ClinicalTrials.gov。这类检索不读取个人健康记录。 |
| 补充提问信息 | 问题中的信息不足时，先向用户确认，再继续处理。 |

回答中的引用可以定位到一条读数、一段原始文档或一份医学资料。点击引用即可核对答案依据。

思考和工具执行过程显示在执行面板中，最终答案单独展示。长对话接近上下文上限时，系统会自动整理早期消息，并在面板中显示整理进度。

点击**停止**会结束浏览器对本轮回答的接收。服务端可能仍在生成；刷新对话后，可以看到已在后台完成的回答。

## 配置 {#configuration}

在**设置 › 模型**中选择模型，也可以按[配置说明](/zh/configuration#the-model-key)修改配置文件。常用设置如下：

| 配置项 | 用途 |
| --- | --- |
| `DEFAULT_MODEL` | 指定 `MODELS` 中默认使用的模型。 |
| `ALLOWED_TOOLS` / `DISALLOWED_TOOLS` | 限制可用工具，白名单优先。将 `python_exec` 加入黑名单即可关闭计算功能。 |
| `AGENT_THINKING` | 设置请求的推理程度：`low`、`medium` 或 `high`，默认 `medium`；设为 `off` 时仍使用 `medium`。模型条目中启用的 `thinking_level` 优先。OCR 与信息提取单独配置。 |
| `KNOWLEDGE_INDEX` | 本地医学资料索引的路径，索引由 `mirobody fetch knowledge` 构建。 |
| `KNOWLEDGE_ONLINE` | 启用 PubMed 和 ClinicalTrials.gov 联网检索，检索词会发送到相应服务。 |

有可用的本地或在线资料来源时，才会提供医学知识工具。计算功能需要按上文说明连接本地 Docker。可运行 `mirobody doctor --probe` 检查模型能力，包括接口是否返回可见的思考内容。

## 接入自定义 agent {#replacing-the-agent}

部署时可以通过 `AGENT_DIRS`，或已安装包的 `mirobody.agents` 入口点，替换内置 agent。若要在其他应用中复用 harness，可安装 `mirobody[agent]`。接口约定与示例插件见 <OssLink path="mirobody/agent/README.md" />。
