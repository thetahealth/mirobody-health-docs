所有聊天模型都使用同一个 `python_exec` 工具。代码可以由云端模型生成，执行过程使用应用所在机器的本地 Docker 服务。计算容器不挂载应用目录，不接收数据库凭据，也不能访问网络。

数据通过已有查询工具的 `Envelope`、`ToolMessage.artifact` 和注入的 `ToolRuntime` 传入本地计算容器中的 JSON。模型只提供代码，无需将压缩后的展示表格重新抄写为参数。常量列、嵌套记录、JSON 数值类型、引用 `rid` 和查询元数据都会保留。健康指标、用药、基因型和药物基因组数据使用同一条数据通路。

## 输入与输出 {#输入与输出}

- `data`：最近一次成功且非空的记录查询所返回的原始行。
- `results`：当前轮次内成功查询的完整信封，包含 `data`、`meta`、`tool`、`tool_call_id`、假设和来源信息。
- `/workspace/data.json`：同一份含有 `data` 和 `results` 的 JSON。它是计算容器内的路径，不是文档工具使用的上传或文档库路径。

当前轮次从用户最近一次提问开始；harness 的修复指令仍属于该轮次。最近一次查询失败或为空时，计算会被拒绝，不会悄悄复用更早的读数，也不会将缺失数据当作零。已有查询工具的 `stats` 和时间分桶视图能够提供的统计，应直接使用对应视图；Python 用于额外计算及跨查询结果的比较。

代码应打印计算结果及其来源 rid。工具通过 artifact 返回退出状态、输出是否截断，以及所使用的源查询 ID。源结果不完整时，会在输出前明确说明。较长的工具文本沿用 harness 的文件卸载机制；超过执行器 40,000 字节预算的输出会明确标记为不完整。

## 本地配置 {#本地配置}

安装 agent 或应用依赖，并预先准备计算镜像：

```bash
pip install -e '.[app,test]'
docker pull python:3.12-slim
```

macOS 的 Docker Desktop、Colima，以及 Linux 的 Docker Engine 均通过本地 Unix socket 连接。执行器依次检查 `PYTHON_SANDBOX_DOCKER_HOST`、`DOCKER_HOST`、`/var/run/docker.sock` 和当前 Docker CLI context；TCP 与 SSH Docker 地址会被拒绝。不需要云端沙箱账户或执行 API。

默认镜像提供 Python 标准库。`PYTHON_SANDBOX_IMAGE` 可以指定已经准备好的本地分析镜像。额外依赖需要提前安装到镜像中：计算容器没有网络，也不会收到应用密钥。

应用本身运行在 Docker 中时，也需要连接同一机器上的 Docker 服务。可选的 [compose-python.yaml](https://github.com/thetahealth/mirobody/blob/4ed28c160af9ae0bede547880759e5570b2243df/compose-python.yaml) 将管理 socket 挂载给应用，计算容器不会获得该 socket。这会授予应用管理容器的权限，因此主 Compose 配置不会自动启用该挂载。

将 `PYTHON_DOCKER_SOCKET` 设置为 Docker 服务所在主机的 socket 路径，将 `PYTHON_DOCKER_GID` 设置为其所属组 ID，然后加入覆盖配置：

```bash
docker compose -f compose.yaml -f compose-python.yaml up -d
```

本地执行器不可用时，工具会报告执行环境配置问题；已经查询到的读数仍然有效。只需要现有查询视图的部署可以通过 `DISALLOWED_TOOLS: [python_exec]` 隐藏计算工具。提示词根据实际提供的工具列表确定计算能力。

## 运行约束与验证 {#运行约束与验证}

`LocalPythonSandbox` 继承 Deep Agents 的 `BaseSandbox`，使用 Docker SDK 管理本地连接和容器生命周期，并复用文件系统辅助方法及标准执行返回结构。模型获得的是 Python 工具，通用 shell 执行工具不会暴露给它。原有只读文档视图和单一 agent harness 保持一致。

每次计算使用 UID/GID 65534、只读镜像、容器自身的 tmpfs、一个 CPU、512 MB 内存及 64 个进程的上限。输出在流式读取时限制大小。命令期限为 1 至 30 秒，宿主等待上限为该期限加 10 秒；超时或取消时会关闭流与容器。容器的有限租期与自动删除机制负责清理应用退出后遗留的计算，正常结束时会更早清理。

原始数据传递和本地生命周期检查：

```bash
pytest -q tests/test_code_tool_capability.py tests/agent/test_code_tool_probe.py
```

检查覆盖常量列、单条记录、带相位的基因型、嵌套注释、多来源、部分结果元数据、输出截断及真实 Docker 超时清理。[语言探针](https://github.com/thetahealth/mirobody/blob/4ed28c160af9ae0bede547880759e5570b2243df/benchmarks/local_agent/README.md)使用合成记录和实际 Python 工具，通过改变输入数据后的重放检查计算行为，不需要再次请求模型。

旧的 `eval`/QuickJS 解释器、PTC 桥接和按模型配置的 `code_tool`、`eval_fetch` 已移除。JavaScript 仅保留为比较评测中可选的 Node 容器。

参考：[Deep Agents 沙箱架构](https://docs.langchain.com/oss/python/deepagents/sandboxes#the-execute-method)、[本地 shell 的限制](https://docs.langchain.com/oss/python/deepagents/backends#localshellbackend-local-shell)。`LocalShellBackend` 不隔离应用文件；这里复用其后端接口，同时使用本地容器作为隔离边界。
