自带 agent 使用的健康数据工具也通过 Model Context Protocol 在 **`/mcp`** 上提供。Claude Desktop、Cursor 或你自己的 agent 循环等 MCP 客户端，可以调用这些工具访问同一份个人记录。另有一个通过 stdio 提供术语工具的服务，不访问个人记录。

## 端点

| 路由 | 识别调用者的方式 | 用途 |
| --- | --- | --- |
| `POST /mcp` | `Authorization: Bearer <access token>` | 能发送请求头的客户端 |
| `POST /mcp/<secret>` | 路径中的 secret | 个人 URL，供无法发送请求头的客户端使用 |
| `GET /personal/mcp` | `Authorization: Bearer <access token>` | 列出调用者创建的链接，以及别人创建的、能读取调用者本人记录的链接 |
| `POST /personal/mcp` | `Authorization: Bearer <access token>` | 替换调用者的个人 URL（body 中带 `user_id` 时，替换的是某位家庭成员指向该人的链接） |
| `DELETE /personal/mcp` | `Authorization: Bearer <access token>` | 吊销调用者为该人创建的链接（自己的，或请求体带 `user_id` 时为家庭成员创建的那条） |
| `DELETE /personal/mcp/<id>` | `Authorization: Bearer <access token>` | 按 id 吊销一条链接，无论它是调用者创建的还是读取调用者本人记录的 |

设置了 `HTTP_URI_PREFIX` 时，以上路由都位于该前缀之下。在 Docker 栈上，服务端监听端口 <Fact k="port" />。

## 个人 MCP URL

个人 URL 自带凭据，桌面客户端因此不需要走登录流程。Web 客户端在**设置 → MCP** 中显示它；你自己的客户端可以用已持有的 access token 生成：

```bash
# 用演示账号登录（真实部署按其用户的方式登录）
TOKEN=$(curl -s -X POST http://localhost:18060/email/verify \
  -H 'Content-Type: application/json' \
  -d '{"email": "you@mirobody.ai", "code": "111111"}' | jq -r .data.access_token)

curl -s -X POST http://localhost:18060/personal/mcp -H "Authorization: Bearer $TOKEN"
```

```json
{ "code": 0, "msg": "ok", "data": { "url": "http://localhost:18060/mcp/<secret>" } }
```

再次生成会**替换**原来的 URL：它会吊销同一对创建者与被读取人之间正在生效的链接，并签发一个新的 secret，有效期从这一刻起算 `MCP_URL_TTL_DAYS` 天（默认 <Fact k="mcpUrlTtlDays" /> 天），使用不会延长有效期。`GET /personal/mcp` 列出调用者能看到的所有生效链接：自己创建的（为自己，或在拥有关爱圈读权限时为他人创建的），以及某位家庭成员创建的、读取调用者本人记录的链接。`DELETE /personal/mcp/<id>` 按 `id` 吊销一条链接，无论调用者是创建者还是被读取的本人；调用者管不到的链接一律回应 404，与不存在的链接一样。

停止共享、退出关爱圈，或创建者的账号被原持有人收回，都会让链接在下一次使用时失效；停止共享或被移出关爱圈还会直接吊销链接，所以之后重新共享也不会让旧链接自动恢复。

<Warning>
1.5.3 之前创建的每一条个人 MCP 链接都已失效：旧的存储方式只按被读取人记录一条链接，没有创建者信息可核对，无法区分谁的链接是谁的。请在设置中重新生成。
</Warning>

<Warning>
secret 就是完整的凭据：任何持有这个 URL 的人都能读取对应那个人的健康记录。它会出现在客户端配置文件和截图里，所以请像对待密码一样对待它：设备丢失时吊销；部署可从网络访问后，只通过 HTTPS 提供。
</Warning>

URL 的开头是请求到达时使用的源。位于反向代理之后时，只有服务端信任代理转发的请求头，这个源才正确，见[在服务器上部署](/zh/deployment/production#public-url-and-https)。

## 账号能看到的工具

端点提供以下工具：

<Fact k="tools.mcp" code sep="、" />

`tools/list` 按账号过滤：账号中没有某类数据时，对应的数据工具会被隐藏，客户端因此不会看到一个只能回答“没有数据”的工具。参与过滤的是 <Fact k="tools.gated" code sep="、" />。每个工具接受什么参数、返回什么，见[健康数据工具](/zh/tools/overview)；你自己添加的工具也以同样方式提供，见[添加工具](/zh/tools/adding-tools)。

仅用于对话的工具（文件工具、`eval` 与 `ask_user`）不通过 MCP 提供。

## 连接客户端

把下文中的 URL 换成你的个人 URL。

<Tabs>
  <Tab title="Cursor">
    Cursor 可以直接连接远程服务。在 `~/.cursor/mcp.json` 或项目中的 `.cursor/mcp.json` 里添加：

    ```json
    {
      "mcpServers": {
        "mirobody": { "url": "http://localhost:18060/mcp/<secret>" }
      }
    }
    ```
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http mirobody http://localhost:18060/mcp/<secret>
    ```
  </Tab>
  <Tab title="Claude Desktop">
    Claude Desktop 以自定义连接器的方式添加远程服务，需要一个它能访问到的 HTTPS 地址。对于运行在你自己机器上的引擎，请改为在 `claude_desktop_config.json` 中通过 stdio 桥接：

    ```json
    {
      "mcpServers": {
        "mirobody": {
          "command": "npx",
          "args": ["-y", "mcp-remote", "http://localhost:18060/mcp/<secret>"]
        }
      }
    }
    ```
  </Tab>
</Tabs>

你自己的 agent 循环可以用任意 MCP 客户端库调用该端点。服务端使用当前的无状态协议版本，并能为仍使用 `initialize` 握手的客户端协商降级。

## 通过 stdio 使用本地术语工具

如果只需术语查询，无须运行服务端或创建个人记录。运行 `uvx mirobody mcp`，即可从已发布的软件包启动 stdio MCP 服务。如果已经安装 Mirobody，也可以运行 `mirobody mcp`。读数、主诉、指标及单位的标准化无须数据库或模型密钥。

在支持启动本地 MCP 进程的客户端中，使用以下配置：

```json
{
  "mcpServers": {
    "mirobody": {
      "command": "uvx",
      "args": ["mirobody", "mcp"]
    }
  }
}
```

该服务提供 `standardize_reading`，将读数转为带 LOINC 和 UCUM 编码的 FHIR Observation；`standardize_complaint` 对主诉做 ICPC-3 编码；`resolve_indicator`、`normalize_unit` 和 `convert_unit` 用于术语查询。`standardize_report` 可以读取 PDF、图片、表格或文本报告；该工具还需要 `mirobody[parse]` 扩展与模型密钥，文档内容会发送给选定的模型服务商。使用 uvx 时，可以运行 `uvx --from 'mirobody[parse]' mirobody mcp` 来启用这个工具。需要访问个人健康记录时，请使用上文的个人 URL。

协议实现与按账号过滤的逻辑位于 <OssLink path="mirobody/mcp/" />。
