在 Web 客户端的**数据**页上传报告。Mirobody 保留原文件，并提取能够识别的读数，
包括报告中注明的单位、参考范围和日期。

## 支持的格式 {#支持的格式}

| 文件              | 处理方式                       |
| --------------- | -------------------------- |
| PDF             | 直接读取文字层，扫描页交由 OCR 或视觉模型识别。 |
| 图片              | 使用已配置的 OCR 或视觉模型识别文字。      |
| Excel           | 读取 `.xlsx`、`.xlsm` 表格。     |
| Word、PowerPoint | 读取 `.docx`、`.pptx` 内容。     |
| 文本与结构化文本        | 支持 TXT、CSV、JSON、HTML 等格式。  |

旧版 `.xls`、`.xlsb`、`.doc`、`.ppt` 不受支持，请先转换格式。
原始基因型导出文件使用单独的[基因数据导入流程](/zh/concepts/genetics)。

## 上传后的检查 {#上传后的检查}

1. 确认当前选中的用户，再上传资料。
2. 等待上传和提取分别完成。文件已保存，不代表已经成功提取读数。
3. 对照原文件检查日期、数值、单位和参考范围，先更正不确定的结果。
4. 在指标页查看记录，或直接提问；回答中的引用可定位到原始资料。

能够识别的表格会优先在本地处理，其余内容交由配置的模型处理。
如需让图片留在本机，请按[选择模型](/zh/model-choice)配置本地或混合方案。

## API 接入 {#api-接入}

REST 上传使用 `POST /files/upload`；需要进度通知时使用 `/ws/upload-health-report`。
WebSocket 客户端应等待 `extraction_completed`，不能把 `upload_completed` 当作提取完成。
请求需要登录凭据，以及目标记录的写入权限；当前参数以部署服务的 `/docs` 为准。

文件已保存却没有读数时，先检查提取状态、模型配置，以及 `ENABLE_INDICATOR_EXTRACTION`。
完整消息格式、示例和错误说明见[文件处理参考](https://github.com/thetahealth/mirobody/blob/7775b50a55e17c98e1c02dfb93fb544dbccd1504/docs/file-processing.md)。
