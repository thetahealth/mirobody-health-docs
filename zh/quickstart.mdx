三种运行方式，不是三个步骤：选与你的目的相符的那一行，另外两行可以忽略。

| 你想要 | 前往 | 需要 | 密钥 |
| --- | --- | --- | --- |
| 在自己的代码里解析名称与单位 | [A · 作为库使用](#a--the-library) | Python 3.12 | 不需要 |
| 运行完整产品，并带有数据 | [B · 完整的栈](#b--the-stack) | Docker | 使用模型功能时需一个；用 llama.cpp 上的本地模型则不需要 |
| 修改代码并查看效果 | [C · 源码检出](#c--a-checkout) | Python 与一个 Postgres | 一个 |

如果使用托管 API 密钥和 `/v1` 接口，请阅读单独的 [Cloud 快速开始](/zh/api-reference/quickstart)。本页介绍开源引擎及其运行命令。

## A · 作为库使用 {#a--the-library}

两个包，唯一的依赖是 numpy。不需要密钥、网络或数据库，本机也不运行任何模型：解析器是基于 LOINC 的词法索引，而不是 LLM。

```bash
pip install mirobody
mirobody resolve "LDL cholesterol" 血红蛋白 ヘモグロビン "空腹血糖(GLU)" 血脂
```

`血脂` 指的是一类检查，而不是某一项观测，所以它解析不出结果。这是有意的设计：错误的编码会把两项不同的检查放到同一条趋势线上。

读取厂商导出包不需要任何额外依赖，`zipfile` 与 `xml.etree` 都在标准库中：

```bash
mirobody import apple ~/Downloads/export.zip
```

其余功能：`pip install 'mirobody[parse]'` 用于把 PDF、照片或表格变成读数（这一项会调用模型，所以需要密钥），`pip install 'mirobody[app]'` 用于服务端。上面的用法两者都不需要。（`[agent]` 是作为库使用的智能体外壳，`[test]` 是测试套件。）

## B · 完整的栈 {#b--the-stack}

Postgres + pgvector、服务端与 worker，演示记录已经预先写入。

```bash
git clone --depth 1 https://github.com/thetahealth/mirobody.git && cd mirobody
./deploy.sh                       # → 在 http://localhost:18060 上打印首次设置页的链接
```

`deploy.sh` 会拉取应用镜像（其中已包含 LOINC 术语包），并在首次运行时写出带有自动生成密钥的 `.env`。Docker 方式不需要 Git LFS。尚未设置模型时，它会打印首次设置页的链接：在那里粘贴**一个**模型密钥，或者选择**100% 在本机运行**，让所有模型都在本地的 [llama.cpp](/zh/local-models) 上运行（`llama-server`，Mirobody 自带预设的本地模型运行时；默认的一对模型需要 16 GB 内存、不需要 GPU，没有 GPU 时第一个回答要 2–3 分钟）。密钥也可以写进 `.env`，然后执行 `docker compose up -d`（`restart` 不会重新读取 `.env`）。在服务容器内检查可用的模型功能：

```bash
docker compose exec mirobody mirobody doctor
```

以 `you@mirobody.ai` 登录，验证码 `111111`，不需要邮件服务。`SEED_DEMO_DATA` 默认开启，两个账号里已经有共 2,019 条读数。如果打算保存真实数据，请在首次启动前把它设为 `false`，两个账号都不会创建。

[`demo/upload/`](https://github.com/thetahealth/mirobody/tree/43892ca6d85e3df1203fca8ceb547debd7947e74/demo) 中有四个文件有意没有预先写入，把其中一个拖到 Data 页面，就会执行实际的文件处理流程。

## C · 源码检出 {#c--a-checkout}

`serve` 是部署形态：它读取随包分发的配置以及任意 `config.{ENV}.yaml` 覆盖文件，并要求密钥能持久保存。`dev` 在同一个进程里运行同一个服务端，配置只存在于内存中，密钥自动生成：

```bash
git clone --depth 1 https://github.com/thetahealth/mirobody.git && cd mirobody
git lfs install && git lfs pull
python3.12 -m venv .venv && . .venv/bin/activate
pip install -e '.[app]'
```

如果没有带 pgvector 的 Postgres，先启动一个：

```bash
docker run -d -p 5432:5432 -e POSTGRES_USER=user -e POSTGRES_PASSWORD=pw \
    -e POSTGRES_DB=mirobody \
    pgvector/pgvector:pg17
```

然后启动 API。如果使用已有数据库，请替换连接地址。在另一个终端调用健康检查：

```bash
mirobody dev --pg-url postgres://user:pw@localhost:5432/mirobody
```

```bash
curl -fsS http://127.0.0.1:18090/api/health
```

响应包含 `version` 字段。数据库需要 pgvector：首次启动时创建的 schema 包含向量列。

**`dev` 提供的是 API，不包括 Web 客户端。** 构建好的客户端位于仓库根目录的 `frontend/`，不在包内，所以源码检出里有，`pip install` 安装的没有。`dev` 用于 API、MCP 接口与 agent；需要界面时请用 B。

`dev` 生成的密钥只在本次运行有效：重启后会话与加密的配置值都会失效。在环境变量中设置 `JWT_KEY`、`CONFIG_ENCRYPTION_KEY` 与 `LOG_ENCRYPTION_KEY` 即可保留。

## 无法正常启动时 {#when-it-does-not-come-up}

| 现象 | 原因 |
| --- | --- |
| `mirobody doctor` 输出 `keys present : none`，且每个用途都是 `--` | 没有模型密钥，也没有本地模型服务。① 收集与 ② 转译照常工作，抽取与回答不可用。打开 `./deploy.sh` 打印的链接。 |
| 新克隆的仓库在查询 LOINC 时报错 | 还没有执行 `git lfs pull`，术语包仍是指针文件。 |
| `mirobody dev` 退出并要求提供 Postgres | 传入 `--pg-url`，或在环境变量中设置 `PG_URL` / `DATABASE_URL`。 |
| 服务端已启动，但设备同步从不执行 | 检查 worker 日志与 Postgres 连接：设备拉取与任务状态都保存在 Postgres 中。 |
| `mirobody serve` 无法连接 Postgres | 为该数据库设置 `PG_HOST`、`PG_PORT`、`PG_USER`、`PG_PASSWORD` 与 `PG_DBNAME`。 |
