完整恢复需要数据库、上传文件，以及与数据匹配的加密密钥。
应用镜像和模型可以重新下载，数据与密钥则需要自行保存。

## 创建备份 {#创建备份}

在部署所用的仓库目录执行，并保持 Postgres 运行：

```bash
shell/backup.sh
# 也可指定其他保存位置：
BACKUP_DIR=/mnt/nas/mirobody shell/backup.sh
```

脚本会生成数据库转储，以及实际存在的本地上传文件归档。
请另存一份到应用主机之外。

## 单独保存的内容 {#单独保存的内容}

| 内容                                      | 原因                     |
| --------------------------------------- | ---------------------- |
| `.env`、生效的配置覆盖文件、密钥 YAML 和 Compose 覆盖文件 | 脚本不备份配置与加密密钥。          |
| 外部存储桶                                   | S3、OSS 中的文件不属于本地上传卷备份。 |
| 当前版本或提交号                                | 恢复时需要选择兼容的代码版本。        |

重新生成的密钥无法解密旧数据。请妥善保存备份对应的密钥，不要提交到代码仓库。

## 核验与恢复 {#核验与恢复}

归档目录能够读取，不代表整套应用已经验证可恢复。
应在隔离环境演练恢复，检查一份代表性的记录和上传文件，避免连接生产数据卷。

恢复命令见[核验与恢复备份](/zh/deployment/restore)。
数据卷名称、保留周期和旧版本迁移规则见[备份技术参考](https://github.com/thetahealth/mirobody/blob/9df0c3850b0d89f70dd5190d843ead757dd0e9f6/docs/backup-restore.md)。
