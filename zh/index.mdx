## 什么是 Mirobody？

**Mirobody** 是一套你自己运行的开源健康数据引擎。它读入化验单、穿戴设备导出、照片和基因文件，为每个值分配一个规范编码与单位，把记录保存在你自己运维的 Postgres 中，并让 agent 基于这份记录回答问题、说明每条读数的来源。从 1.5.4 起，所有模型都可以在同一台机器上运行（基于 [llama.cpp](/zh/local-models)），你的文档和提问就不必离开这台机器；记录可以导出、备份和恢复为你自己保管的文件。引擎以 Apache 2.0 许可[开源](https://github.com/thetahealth/mirobody)，由 Theta Health 开发，也是其 Theta Wellness 应用底层的引擎。**Mirobody Cloud** 以托管 API 的形式提供同样的标准化与 agent 能力。

## 开始使用

先选择记录在哪里运行。两条路径采用同一套编码方式，但部署步骤和 API 端点不同。

<RunModes />

| 第一个目标 | 从这里开始 | 验证结果 |
| --- | --- | --- |
| 调用托管 API | [Cloud 快速开始](/zh/api-reference/quickstart) | 两条样例读数具有相同的 LOINC 编码，提问时可以引用它们。 |
| 在本地解析名称或单位 | [作为库使用](/zh/quickstart#a--the-library) | 无须数据库或模型密钥即可返回编码。 |
| 在本地体验完整产品 | [Docker 演示](/zh/self-host#first-local-result) | 服务健康，**Data** 页面显示演示读数。 |
| 把提问和文档都留在一台机器上 | [本地运行](/zh/local-models) | `.env` 中没有任何密钥时，`mirobody doctor --probe` 对本地条目报告 PASS。 |
| 按你需要的隐私和回答质量选择模型 | [选择模型](/zh/model-choice) | `mirobody doctor --probe` 对你选的模型报告 PASS。 |

## 从数据到回答

  <img alt="收集、转译、智能体：健康数据从来源进入编码记录，再用于回答" src="/images/oss/docs/images/collect-translate-agent.zh-CN.svg" className="block dark:hidden" />
  <img alt="收集、转译、智能体：健康数据从来源进入编码记录，再用于回答" src="/images/oss/docs/images/collect-translate-agent-dark.zh-CN.svg" className="hidden dark:block" />

| 阶段 | 可验证的结果 | 延伸阅读 |
| --- | --- | --- |
| **① 收集** | 文件、设备读数或结构化记录连同来源进入系统。 | [Cloud 数据入口](/zh/api-reference/index#data-inputs) · [开源数据管线](/zh/concepts/architecture) |
| **② 转译** | 同一项检查的不同名称归入规范的 LOINC 编码；单位采用 UCUM。无法匹配的名称保持未匹配。 | [标准化](/zh/concepts/indicators) |
| **③ 智能体** | agent 查询编码后的记录，返回带有读数依据的回答。 | [Cloud 问答 API](/zh/api-reference/chat) · [开源 agent](/zh/tools/agents) |

使用 Cloud 时，应用向 `/v1` 提交数据，由托管服务保存和处理。自部署时，引擎运行在你管理的基础设施上。两种方式的能力分别见 [Cloud 简介](/zh/api-reference/index)和[本地部署指南](/zh/self-host)。

## 存储与运维

| 选择依据 | Mirobody Cloud | 自部署 |
| --- | --- | --- |
| 记录存储 | 由 Mirobody 运维，遵循 API 的留存设置 | 保存在你的 Postgres 和文件存储中 |
| 模型请求（模型厂商密钥） | 由托管服务处理 | 发往你粘贴密钥的那家厂商，受其条款约束 |
| 模型请求（100% 在本机运行） | 不提供：Cloud 自行运行模型 | 由同一台机器上的 llama.cpp 提供；与你有关的任何数据都不会发出 |
| 取回数据 | [数据生命周期](/zh/api-reference/lifecycle)：留存与 Subject 下线 | CSV、JSON 与 NDJSON 导出，基因型导出为 VCF，以及备份脚本，见[导出数据](/zh/deployment/export) |
| 部署与升级 | 由 Mirobody 运维 | 按[服务器部署指南](/zh/deployment/production)操作 |
