The engine ships one agent. It answers the questions asked at `/ask` in the web client and through the chat API, over the coded record of the person the question is about. Adding a capability means adding a [tool](/en/tools/adding-tools), not another agent.

Every agent runtime other than the bundled one (Claude Code, Codex, Cursor, Gemini CLI, Claude Desktop, an agent loop of your own) reaches the same data through the [MCP endpoint](/en/tools/mcp-integration) and needs nothing from this page.

## What a turn can use

| | What it is |
| --- | --- |
| Health-data tools | <Fact k="tools.mcp" code />: the same tools any MCP client sees over `/mcp`; see [Health-Data Tools](/en/tools/overview) |
| Virtual filesystem | `/uploads`, `/library` and `/memories`: read-only views of the person's files and profile, with file tools to list, read and search them |
| Code execution | `python_exec` runs Python on original record-tool results in a local container, without application mounts, credentials or network access; see [Local Python Analysis](/en/tools/python-analysis) |
| One question back | `ask_user`, which pauses the turn to ask the person a question; the next message answers it. It is never exposed over MCP. |
| Medical knowledge | `search_medical_knowledge` and `read_medical_source`: MedlinePlus health topics and lab test pages and FDA labels from a local index, plus PubMed and ClinicalTrials.gov when online search is on. They do not read the record. The agent and signed-in MCP clients can use them when a local or online knowledge source is available. |
| Memory | Conversation state per session, stored in Postgres |

Each answer streams as typed blocks. Visible reasoning appears immediately in the work panel, alongside tool execution and context-summary activity. Tool narration stays in that panel; final answer text is released when the answering model step finishes. Copy includes only the final answer.

The panel distinguishes running, failed, partial and unfinished tools, and preserves expansion and scroll choices. Earlier messages are summarized automatically when the conversation approaches the configured context limit; the panel reports actual summary activity without displaying the summary text.

Stop ends reception in the browser. The server continues background generation after disconnect and may save a completed answer that appears when history is refreshed.

Every number in an answer cites what it rests on: a row a tool showed in the conversation (`r3`), a reference passage (`ref:medlineplus_test:alt-blood-test`), or lines of a document (`/library/report.pdf#L12-L14`). The web client draws each cite as a numbered chip; `GET /api/citations` resolves it to the reading as it is now, its file, or the reference page.

## Configuration {#configuration}

The agent's keys have no agent-name suffix. The shipped values live in `config.llm.yaml`; override them in your overlay.

| Key | What it sets |
| --- | --- |
| `MODELS` | The model picker: one entry per chat model. `/api/models` lists the entries whose key or server is present, and a chat request picks one by name. The `local` entry appears once `LOCAL_BASE_URL` is set, labelled with the model it runs. |
| `DEFAULT_MODEL` | The picker's default; unset, the first entry whose key is present |
| `ALLOWED_TOOLS` / `DISALLOWED_TOOLS` | A tool whitelist or blacklist; the whitelist wins. Listing `python_exec` in `DISALLOWED_TOOLS` turns code execution off. |
| `PROMPTS` | System prompt templates, as a path or `path@name`; the first is the default |
| `AGENT_NAME` | The persona name used in the prompt |
| `AGENT_CHECKPOINTER` | `true` keeps conversation state per session; `false` makes every turn start fresh |
| `AGENT_THINKING` | Requested reasoning effort for chat models: `low`, `medium` (the default) or `high`. `off` or an unset value selects `medium`; a positive `thinking_level` in a `MODELS` entry takes precedence. OCR and extraction models keep separate settings. |
| `KNOWLEDGE_INDEX` | The local medical-knowledge index `mirobody fetch knowledge` builds; unset, `~/.mirobody/knowledge/medref.sqlite3`. The Docker build attempts to prepare one. Without the file the local tier is off. |
| `KNOWLEDGE_ONLINE` | `true` adds PubMed (through Europe PMC) and ClinicalTrials.gov to the knowledge search. Each search sends its words to those hosts, never record data. |

A model entry's `profile.max_input_tokens` controls the context budget and automatic summarization thresholds. Set it to a window the model endpoint can accept. Summary generation fails explicitly if the selected input exceeds that budget or the model returns an empty or truncated summary.

The app requests thinking through supported model interfaces. `mirobody doctor --probe` checks a tool round trip and whether reasoning is actually visible; an endpoint that withholds it cannot supply a thinking stream. The former per-model `eval_fetch` and `code_tool` switches are no longer used. To enable local calculation, follow [Local Python Analysis](/en/tools/python-analysis).

Model selection and keys are described in [Configuration](/en/configuration#the-model-key).

## Replacing the agent {#replacing-the-agent}

There is one agent slot. A replacement comes from an installed package that declares a `mirobody.agents` entry point, or from a directory listed in `AGENT_DIRS`; the first class found that defines `generate_response` becomes the agent for the process. Nothing in the package needs editing.

The contract is two methods. `generate_response` receives the user the turn is about (already authorized, and possibly a care-circle member rather than the caller), this turn's messages, and keyword arguments such as `language`, `session_id` and `timezone`; it yields the same typed blocks the shipped agent streams. Accept `**kwargs`, since the chat layer may add arguments.

```python
class MyAgent:
    def __init__(self, **kwargs): ...

    async def generate_response(self, user_id: str, messages: list[dict], **kwargs):
        yield {"type": "text", "text": "..."}
```

To build a different harness on the shipped middleware and filesystem backends instead, install `mirobody[agent]`. The full contract, the block vocabulary and a minimal example plugin are in <OssLink path="mirobody/agent/README.md" />.
