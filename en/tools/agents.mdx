The built-in agent answers questions about the selected person's health record. Use it in the web client at `/ask` or through the chat API. To use Claude Code, Codex, Cursor or another external agent, connect through [MCP](/en/tools/mcp-integration).

## Available tools

| Task | How it works |
| --- | --- |
| Compare health records | Query measurements, medications and genetic data; see [Health-Data Tools](/en/tools/overview). |
| Read source documents | Search and read the person's uploaded files and document library. |
| Calculate from records | Use `python_exec` to calculate from the original query results in a local container. See [Local Python Analysis](/en/tools/python-analysis) for setup. |
| Look up medical references | Search a local medical-reference index or, when enabled, PubMed and ClinicalTrials.gov. These tools do not query the person's record. |
| Clarify a question | Ask the user for missing information before continuing. |

Citations link an answer to a recorded reading, a document passage or a medical reference. Open a citation to check the source behind the answer.

Reasoning and tool activity appear in the work panel; the final answer appears separately. Long conversations are summarized automatically as they approach the context limit. The panel shows when summarization is in progress.

**Stop** ends reception in the browser. Generation may continue on the server, so a completed answer can appear when you refresh the conversation.

## Configuration {#configuration}

Choose a model in **Settings › Model** or follow [Configuration](/en/configuration#the-model-key). The main agent settings are:

| Setting | Purpose |
| --- | --- |
| `DEFAULT_MODEL` | The default entry from `MODELS`. |
| `ALLOWED_TOOLS` / `DISALLOWED_TOOLS` | Limit available tools. The allowlist takes precedence; adding `python_exec` to the denylist disables calculation. |
| `AGENT_THINKING` | Requested reasoning effort: `low`, `medium` or `high`. The default is `medium`; `off` also falls back to `medium`. An enabled model-entry `thinking_level` takes precedence. OCR and extraction have separate settings. |
| `KNOWLEDGE_INDEX` | Path to a local medical-reference index built with `mirobody fetch knowledge`. |
| `KNOWLEDGE_ONLINE` | Enable PubMed and ClinicalTrials.gov searches. Search terms are sent to those services. |

Knowledge tools appear only when a local or online source is available. Calculation needs the local Docker setup described above. `mirobody doctor --probe` checks model capabilities, including whether the endpoint returns visible reasoning.

## Custom agents {#replacing-the-agent}

A deployment can replace the built-in agent through `AGENT_DIRS` or an installed package's `mirobody.agents` entry point. To reuse the harness in another application, install `mirobody[agent]`. The integration contract and example plugin are in <OssLink path="mirobody/agent/README.md" />.
