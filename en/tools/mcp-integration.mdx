Connect Claude Code, Codex, Cursor or another MCP client to your records through **`/mcp`**. For offline terminology lookups without personal records, use the stdio server described below.

The client controls where retrieved data is sent. A cloud assistant receives the readings it requests even if Mirobody uses [local models](/en/local-models). To keep the whole interaction local, the client must also use a local model.

## Endpoints

| Route | Identifies the caller by | Use |
| --- | --- | --- |
| `POST /mcp` | `Authorization: Bearer <access token>` | A client that can send a header |
| `POST /mcp/<secret>` | The secret in the path | A personal URL, for a client that cannot send a header |
| `GET /personal/mcp` | `Authorization: Bearer <access token>` | Lists the links the caller made and the ones reading the caller's record |
| `POST /personal/mcp` | `Authorization: Bearer <access token>` | Replaces the caller's personal URL (or, with `user_id` in the body, a family member's link to that person) |
| `DELETE /personal/mcp` | `Authorization: Bearer <access token>` | Revokes the link the caller made for that person (their own, or with `user_id` in the body, a family member's) |
| `DELETE /personal/mcp/<id>` | `Authorization: Bearer <access token>` | Revokes one link by id, made by the caller or reading the caller's record |

All of these sit under `HTTP_URI_PREFIX` when one is set. On the Docker stack the server listens on port <Fact k="port" />.

## Personal MCP URL

A personal URL carries its own credential, so a desktop client needs no sign-in flow. The web client shows it under **Settings → MCP**; your own client mints it with the access token it already holds:

```bash
# sign in with a demo account (a real deployment signs in the way its users do)
TOKEN=$(curl -s -X POST http://localhost:18060/email/verify \
  -H 'Content-Type: application/json' \
  -d '{"email": "you@mirobody.ai", "code": "111111"}' | jq -r .data.access_token)

curl -s -X POST http://localhost:18060/personal/mcp -H "Authorization: Bearer $TOKEN"
```

```json
{ "code": 0, "msg": "ok", "data": { "url": "http://localhost:18060/mcp/<secret>" } }
```

Generating a new URL revokes the previous link for the same creator and record. Links expire after `MCP_URL_TTL_DAYS` days (<Fact k="mcpUrlTtlDays" /> by default); using a link does not extend it. Use Settings or the endpoints above to view and revoke links.

A link stops working when its sharing permissions or creator authorization end. Sharing the record again does not reactivate a revoked link.

<Warning>
Treat a personal URL like a password: anyone who has it can read the linked record. Keep it out of screenshots and public configuration, revoke it if a device is lost, and use HTTPS for network access.
</Warning>

The URL starts with the origin the request arrived on. Behind a reverse proxy, that origin is only correct when the server trusts the proxy's forwarded headers; see [Deploy on a Server](/en/deployment/production#public-url-and-https).

## Tools an account sees

The endpoint serves these tools:

`tools/list` is filtered per account: a data tool is hidden from an account that holds none of that data, so a client never sees a tool whose only answer would be "no data". The filtered tools are <Fact k="tools.gated" code />. What each tool accepts and returns is in [Health-Data Tools](/en/tools/overview), and tools you add yourself are served the same way; see [Adding Tools](/en/tools/adding-tools).

The chat-only tools (the file tools, `python_exec` and `ask_user`) are not served over MCP.

## Connect a client

Replace the URL below with your personal URL.

<Tabs>
  <Tab title="Cursor">
    Cursor connects to a remote server directly. Add it to `~/.cursor/mcp.json`, or to `.cursor/mcp.json` in a project:

    ```json
    {
      "mcpServers": {
        "mirobody": { "url": "http://localhost:18060/mcp/<secret>" }
      }
    }
    ```
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http mirobody http://localhost:18060/mcp/<secret>
    ```
  </Tab>
  <Tab title="Codex">
    ```bash
    codex mcp add mirobody --url http://localhost:18060/mcp/<secret>
    ```
  </Tab>
  <Tab title="Gemini CLI">
    ```bash
    gemini mcp add --transport http mirobody http://localhost:18060/mcp/<secret>
    ```
  </Tab>
  <Tab title="Claude Desktop">
    Claude Desktop adds remote servers as custom connectors, which need an HTTPS URL it can reach. For an engine on your own machine, bridge the URL over stdio instead, in `claude_desktop_config.json`:

    ```json
    {
      "mcpServers": {
        "mirobody": {
          "command": "npx",
          "args": ["-y", "mcp-remote", "http://localhost:18060/mcp/<secret>"]
        }
      }
    }
    ```
  </Tab>
</Tabs>

ChatGPT and claude.ai connect from the cloud as well, so they need an HTTPS address they can reach: [deploy the stack on a server](/en/deployment/production) first. An agent loop of your own calls the endpoint with any MCP client library. The server speaks the current stateless protocol revision and negotiates down for clients that still use the `initialize` handshake.

## Local terminology over stdio

For terminology lookup without a server or personal record, run `uvx --python 3.12 mirobody mcp`. It serves MCP over stdio from the published package; `--python 3.12` lets uv fetch the interpreter the package needs, since an older default picks a release from before 1.2. If Mirobody is already installed, `mirobody mcp` starts the same server. No database or model key is needed for reading, complaint, indicator or unit standardization.

In a client that starts local MCP processes, use this configuration:

```json
{
  "mcpServers": {
    "mirobody": {
      "command": "uvx",
      "args": ["--python", "3.12", "mirobody", "mcp"]
    }
  }
}
```

This server offers `standardize_reading` for FHIR Observations with LOINC and UCUM codes, `standardize_complaint` for ICPC-3, and `resolve_indicator`, `normalize_unit` and `convert_unit` for terminology lookup. Its `standardize_report` tool reads a PDF, image, spreadsheet or text report; that tool additionally needs the `mirobody[parse]` extra and a configured model key, and sends the document to the chosen model provider. To enable it with uvx, run `uvx --python 3.12 --from 'mirobody[parse]' mirobody mcp`. Use the personal URL above when the client needs a person's stored health record.

The protocol implementation and the per-account filter are in <OssLink path="mirobody/mcp/" />.
