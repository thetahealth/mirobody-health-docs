## What is Mirobody?

**Mirobody** is an open-source health data engine you run yourself. It reads lab reports, wearable exports, photos and genetic files, assigns one standard code and unit to each value, keeps the record in a Postgres you operate, and lets an agent answer questions over it while naming the source of every reading. Since 1.5.4 every model can run on the same machine, on [llama.cpp](/en/local-models), so your documents and questions need not leave it, and the record exports, backs up and restores as files you hold. The engine is [open source](https://github.com/thetahealth/mirobody) under Apache 2.0, built by Theta Health, and is the engine under its Theta Wellness app. **Mirobody Cloud** offers the same standardization and agent capabilities as a hosted API.

| Stage | What you can observe | Read more |
| --- | --- | --- |
| **① Collect** | A file, device reading or structured record enters the system with its source. | [Cloud data inputs](/en/api-reference/index#data-inputs) · [Open Source collection](/en/concepts/architecture) |
| **② Translate** | Different names for the same test resolve to a standard LOINC code; units use UCUM. Unmatched names remain unmatched. | [Standardization](/en/concepts/indicators) |
| **③ Agent** | A question runs over the coded record and returns an answer with its supporting readings. | [Cloud Answers API](/en/api-reference/chat) · [Open Source agent](/en/tools/agents) |

On Cloud, your application sends data to `/v1`; the service stores and processes it. In a self-hosted deployment, the engine runs on infrastructure you manage. See [Cloud capabilities](/en/api-reference/index) and [the local setup guide](/en/self-host) for their respective paths.

## Storage and operations

| Decision | Mirobody Cloud | Self-Host |
| --- | --- | --- |
| Stored records | Operated by Mirobody, under the API's retention settings | In your Postgres and file storage |
| Model requests, with a vendor key | Handled by the hosted service | Sent to the vendor whose key you paste, under its terms |
| Model requests, 100% on this machine | Not offered: Cloud runs the models | Served by llama.cpp on the same machine; nothing about you is sent |
| Taking data out | [Data lifecycle](/en/api-reference/lifecycle): retention and Subject offboarding | CSV, JSON and NDJSON exports, VCF for genotypes, and a backup script; see [Export Your Data](/en/deployment/export) |
| Deployment and upgrades | Operated by Mirobody | Follow the [server deployment guide](/en/deployment/production) |
