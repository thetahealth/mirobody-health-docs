Mirobody Cloud provides the hosted `/v1` API for storing health data, standardizing readings, and answering questions over them. Your application collects the data and sends it to the service. For the product overview and the self-hosted path, see [Mirobody](/en).

## Data inputs {#data-inputs}

Send each source to the endpoint that handles its shape. Use the same `user` value for every call that belongs to one Subject.

| Your data | Endpoint | Result |
| --- | --- | --- |
| Device readings or other structured records | [`POST /v1/data`](/en/api-reference/data) | Stored readings with normalized names and units |
| Reports, photos, or spreadsheets | [`POST /v1/files`](/en/api-reference/files) | Stored source file and extracted readings |
| Narrative text or a preview of extraction | [`POST /v1/standardize`](/en/api-reference/extract) | Synchronous standardization result |
| A subjective journal entry | [`POST /v1/responses`](/en/api-reference/responses) with `store: true` | A stored conversation entry |

The [quickstart](/en/api-reference/quickstart) shows a complete structured-record request. The [API overview](/en/api-reference/overview) covers authentication, Subjects, errors, and retention.

## Processing stages

<Steps>
  <Step title="① Collect">
    Your application obtains device data, an uploaded report, or a user entry, then sends it through the matching endpoint above.
  </Step>
  <Step title="② Translate">
    The service matches measurement names to LOINC codes and parses units with UCUM. Inspect the resulting codes in the [standardization guide](/en/api-reference/standardization).
  </Step>
  <Step title="③ Agent">
    Ask about the stored record through the [Answers API](/en/api-reference/chat), or build an agent through the [Agent API](/en/api-reference/responses).
  </Step>
</Steps>

## Answer and agent APIs

| Workflow | Endpoint | Use it for |
| --- | --- | --- |
| Grounded answer | [`POST /v1/chat/completions`](/en/api-reference/chat) | One question with supporting health records |
| Agent workflow | [`POST /v1/responses`](/en/api-reference/responses) | Tools, conversation state, and streaming |

Both use OpenAI-compatible request formats. For runnable Python and Node examples, see [SDK Examples](/en/api-reference/sdk-examples).
