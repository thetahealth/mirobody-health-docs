**データ**ページから報告をアップロードします。Mirobody は元のファイルを保持し、印字された単位・基準範囲・報告日を含め、識別できた測定値を抽出します。

## 対応する文書形式 {#対応する文書形式}

| 形式              | 処理内容                                             |
| --------------- | ------------------------------------------------ |
| PDF             | 埋め込まれたテキストを読み取ります。スキャンしたページは OCR または視覚モデルで認識します。 |
| 画像              | 設定済みの OCR または視覚モデルで文字を認識します。                     |
| Excel           | `.xlsx`、`.xlsm` の表を読み取ります。                       |
| Word・PowerPoint | `.docx`、`.pptx` の内容を読み取ります。                      |
| テキストと構造化テキスト    | TXT、CSV、JSON、HTML など対応するテキスト形式を読み取ります。           |

旧形式の `.xls`、`.xlsb`、`.doc`、`.ppt` には対応していません。先に対応形式へ変換してください。
生の遺伝子型エクスポートは、別の[遺伝子データの取り込み手順](/ja/concepts/genetics)に従います。

## アップロードして確認する {#アップロードして確認する}

1. 対象の記録を選び、文書をアップロードします。
2. アップロードと抽出の両方が終わるまで待ちます。保存済みのファイルでも、抽出に失敗していたり、
   使える測定値が1件もないことがあります。
3. 抽出された日付・数値・単位・基準範囲を元の資料と照合します。確信が持てない結果は、使う前に修正してください。
4. 質問するか、「指標」を開きます。引用は出典までたどれます。

テキストの表は、できる限りローカルで読み取ります。それ以外の内容は設定済みのモデルを使います。
画像をローカルにとどめるには、[モデルの選び方](/ja/model-choice)のローカルまたはハイブリッドの手順に従ってください。

## API 連携 {#api-連携}

REST でアップロードするには `POST /files/upload` を、進捗イベントを受け取るには `/ws/upload-health-report` を使います。REST エンドポイントは、リクエストに `file=true`
も付けない限りファイルを保存するだけです。`file=true` を付けると記録に組み込まれ、抽出が始まります。これは**データ**ページと同じ経路です。WebSocket クライアントは `extraction_completed` を待つ必要があります。`upload_completed` はファイルの保存を確認するだけです。リクエストには認証と、対象の記録への書き込み権限が必要です。現在のリクエストスキーマはデプロイの `/docs` ページで確認できます。

ファイルは保存されたのに測定値が出てこない場合は、抽出状況・モデル設定・ `ENABLE_INDICATOR_EXTRACTION` の設定を確認してください。インターフェースの例、上限、
エラー形式は[ファイル処理リファレンス](https://github.com/thetahealth/mirobody/blob/5681e7176dce2a63fda1f53813ffef292b433dc1/docs/file-processing.md)（英語）にあります。
