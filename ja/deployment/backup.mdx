完全な復元には、データベース・アップロード済みファイル・対応する暗号化キーが必要です。アプリケーションとモデルのイメージは、あらためてダウンロードできます。

## バックアップを作成する {#バックアップを作成する}

Docker デプロイを動かしているチェックアウトから、Postgres を起動した状態で実行します。

```bash
shell/backup.sh
# 保存先を変える場合:
BACKUP_DIR=/mnt/nas/mirobody shell/backup.sh
```

スクリプトは Postgres のダンプを作成し、ローカルアップロードがあればそのアーカイブも作成します。コピーはアプリケーションのホスト以外にも保管してください。

## 別途保管するもの {#別途保管するもの}

| 項目                                                  | 理由                                          |
| --------------------------------------------------- | ------------------------------------------- |
| `.env`、有効な設定の上書きファイル、シークレットの YAML ファイル、Compose の上書き | バックアップスクリプトには設定や暗号化キーが含まれません。               |
| 外部のストレージバケット                                        | S3 や OSS 上のファイルは、ローカルアップロードのバックアップには含まれません。 |
| 実行中のバージョンまたはコミット                                    | 復元時に互換性のあるコードを選ぶために必要です。                    |

新しく生成したキーでは、既存のコンテンツを復号できません。キーはバックアップとあわせて保護しつつ、ソース管理には含めないでください。

## 確認と復元 {#確認と復元}

アーカイブの一覧が読めることは、アプリケーション全体を復元できる証明にはなりません。隔離したデプロイで復元を一度試し、代表的な記録とアップロード済みファイルを開いて確認してください。本番のボリュームはそのテストに使わないでください。

復元コマンドは[バックアップの確認と復元](/ja/deployment/restore)を参照してください。
